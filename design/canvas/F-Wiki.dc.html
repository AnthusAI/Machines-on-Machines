#Durable
execution

A way of running long workflows so that their progress is saved as they go, letting them survive crashes and restarts and resume exactly where they stopped.

Entry drafted by an agent Linked to [N] sources in the corpus Reviewed by [EDITOR NAME] Updated [DATE]

An ordinary program keeps its progress in memory. If the process dies halfway through a multi-step job, that progress is gone, and the job either starts over or is left half-done. Durable execution records each completed step, along with its result, in persistent storage as the workflow runs.

When the workflow restarts, the runtime replays that record: finished steps return their saved results instead of running again, and execution continues from the first step that never completed. Common building blocks include an append-only event history, checkpoints, and timers that can wait for hours or days without holding a process open.

The idea matters for AI agents because agent runs are long, call many external tools, and often pause for a person to approve something. The trade-offs are real: workflow code usually has to be deterministic so replay gives the same path, and side effects such as payments or emails need to be idempotent or guarded so they are not repeated.
